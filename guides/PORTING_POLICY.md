# Porting Policy

`fsrs_ex` is a direct port of the scheduler in `open-spaced-repetition/fsrs-rs`.

## Baseline

- Upstream project: `open-spaced-repetition/fsrs-rs`
- Baseline version: `v7.0.0`
- Algorithms: FSRS-7, plus FSRS-6 and the legacy 17- and 19-parameter formats that fsrs-rs still accepts

Until 0.1.2 the baseline was `py-fsrs` `v6.3.0`. See [Migrating to 7.0](MIGRATING_TO_7.md).

## Versioning

The version of `fsrs_ex` is the version of `fsrs-rs` it is ported from. `fsrs_ex` 7.0.0 corresponds to `fsrs-rs` v7.0.0.

## Scope

Ported: the inference API — model construction and parameter handling, memory state updates, retrievability, interval calculation and the SM-2 bridge (`model.rs`, `model_v6.rs`, `model_v7.rs`, the parameter clippers, and the scheduling functions of `inference.rs`).

Not ported: the optimizer (`compute_parameters` and everything under training), `evaluate` and related metrics, the simulator, and cost-ADR.

## Alignment Priorities

1. **Algorithm semantics first**
   - Keep formulas, clamping and iteration counts identical to upstream.
2. **API shape**
   - Keep function names, argument order and struct fields aligned with the Rust API.
3. **Deterministic parity verification**
   - Use fixtures generated by the Rust crate to detect divergence.

## Allowed Elixir Adaptations

Adaptations are allowed only when they do not change algorithm semantics:

- `{:ok, value}` / `{:error, reason}` tuples in place of `Result`
- `Fsrs.Item` and `Fsrs.Review` as names for `FSRSItem` and `FSRSReview`
- rating atoms (`:again`, `:hard`, `:good`, `:easy`) accepted alongside integers
- 64-bit floats in place of `f32`; results agree with upstream within a small tolerance, not bit for bit
- an `ArithmeticError` raised by the BEAM is reported as `:invalid_input` where fsrs-rs would detect a non-finite result

## Non-goals

- A scheduling layer (cards, due dates, learning steps, fuzzing) that upstream does not have
- Custom FSRS variants
- Silent behavior changes that diverge from the baseline

## Upgrade Workflow

When fsrs-rs publishes a new version:

1. Compare the upstream inference sources, constants and clipping bounds
2. Update the code and tests
3. Bump the `fsrs` version in `test/fixtures/rust_fixture/Cargo.toml`, rename the fixture, and regenerate it
4. Run the parity tests and the full suite
5. Set the package version to the fsrs-rs version and document changes for users
